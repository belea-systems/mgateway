# mgateway

Основной шлюз для получения чрезвычайных сообщений об угрозах ракетных ударов и атак БПЛА по Белгородской области

## Принцип работы шлюза 

Шлюз принимает сообщения из различных источников, проверяет корректность сообщений и в случае если 
сообщение соответствует формату, отправляет его в очередь для анализа и сбора статистики.
Никаких дополнительных операций шлюз не выполняет.

## Интеграция с системой

Для интеграции с системой необходимо реализовать слушатель чрезвычайных сообщений из какого-либо
источника, [пример](https://gitverse.ru/belea/telegram-alert-listener).

После реализации необходимо получить JWT-токен, подписанный при помощи алгоритма HS256.
Для взаимодействия со шлюзом, необходимо в HTTP-запросах указывать в заголовке ```Authorization``` 
полученный токен для аутентификации и авторизации. Пример:
```http request
POST https://<mgateway-address>/emergency-alerts
Authorization: Bearer <токен>

<тело запроса>
```

При получении сообщений источник должен произвести маппинг сообщения и его метаданных в 
следующий формат:
```json
{
  "message": "Текст чрезвычайного сообщения",
  "messageId": "Идентификатор сообщения",
  "sentAt": "Время отправки сообщения со стороны системы откуда считывается сообщение",
  "messageData": {
    "id": "Идентификатор канала",
    "name": "Наименование канала",
    "source": "ИДЕНТИФИКАТОР ИСТОЧНИКА"
  }
}
```
*Примечание: поле ```source``` является перечислением, доступные для получения сообщений системы и приложения:*
- *Telegram - TELEGRAM*
- *Иная система - ANOTHER*

После маппинга слушатель должен отправить POST-запрос с сообщением в качестве тела запроса на 
эндпоинт ```<mgateway-address>/emergency-alerts```, где ```mgateway-address``` - фактический URL-адрес 
шлюза.

В случае если сообщение валидно и шлюз отправил сообщение в очередь для анализа, то клиенту придет ответ 
в формате:
```json
{
  "messageId": "1ef2963b-90c8-4a41-8e12-e9dda3ebaea3"
}
```
где ```messageId``` - идентификатор принятого сообщения в системе в формате UUID

## Дедупликация сообщений

Шлюз хранит информацию для дедупликации чрезвычайных сообщений в виде кортежей вида ```(messageId, messageData.id, messageData.source)```.
Данные кортежи отвечают за логическую дедупликацию, необходимую чтобы в систему не попало одно и то же сообщение дважды. Отсюда следует
обязательность заполнения данных полей в теле сообщений в ином случае сообщение не будет принято.
